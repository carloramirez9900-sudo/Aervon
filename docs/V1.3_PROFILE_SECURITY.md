# AERVON v1.3 — Perfil y seguridad

## Objetivo
Cerrar la experiencia de seguridad de cuenta antes de comenzar el panel administrativo.

## Backend
Nuevos endpoints autenticados:

- `GET /auth/profile` — estado de cuenta, teléfono y Telegram vinculados.
- `GET /auth/sessions` — sesiones refresh activas del usuario.
- `DELETE /auth/sessions/:id` — revoca una sesión distinta de la actual.
- `POST /auth/sessions/revoke-others` — revoca las demás sesiones.
- `POST /auth/password/change` — valida contraseña actual, cambia el hash, revoca sesiones previas y entrega un par de tokens nuevo.

Los JWT emitidos desde esta versión incluyen `sid` (session id), y la respuesta de autenticación expone `sessionId` para identificar el dispositivo actual en la UI.

## Seguridad
- La contraseña actual es obligatoria para cambiar la contraseña.
- La nueva contraseña conserva la política mínima de 10 a 128 caracteres, con letras y números.
- Tras un cambio de contraseña se revocan todas las sesiones anteriores.
- Una sesión solo puede ser revocada por el propietario autenticado de esa cuenta.
- La UI nunca muestra el `telegramUserId`; solo el estado verificado y el username, si existe.
- Las private keys, secrets de Telegram y credenciales blockchain no se exponen en estos endpoints.

## Frontend
Nueva ruta protegida: `/profile`.

Incluye:
- estado de teléfono verificado;
- estado de Telegram vinculado;
- cambio de contraseña con controles de visibilidad;
- lista de sesiones activas;
- cierre individual de sesiones remotas;
- cierre de todas las demás sesiones;
- cierre de sesión actual.

El avatar del header abre Perfil y Seguridad. El logout dejó de ser una acción directa del avatar para evitar cierres accidentales.

## Pendiente de producción
Antes de producción pública se recomienda migrar el refresh token desde `sessionStorage` a cookie `Secure`, `HttpOnly` y `SameSite` (o usar un BFF). Esta versión mantiene el contrato existente para no romper el frontend mientras se completa el producto.
