# AERVON v1.4 — Administration backend

## Security model

Administration uses the normal authenticated user identity plus server-side RBAC stored on the user record. An access token alone does not grant admin access; every `/admin/*` request re-checks the account status and current roles in MongoDB.

Roles:
- `SUPER_ADMIN`: role management, all administrative capabilities.
- `OPERATIONS`: cycles, runtime pause switches, operational views.
- `FINANCE`: deposits, withdrawals, formal ledger adjustments.
- `SUPPORT`: user lookup/status for non-admin accounts.
- `AUDITOR`: read-only operational/audit access.

There is no public endpoint that promotes an account to administrator. The first `SUPER_ADMIN` can be created once with `ADMIN_BOOTSTRAP_ENABLED=true` and `ADMIN_BOOTSTRAP_PHONE`, only when no administrator exists and the phone already belongs to a registered account. Disable the flag after bootstrap.

## Money safety

There is no endpoint that directly writes a user's balance. A finance adjustment creates an `ADMIN_ADJUSTMENT` double-entry ledger transaction. `reason` and `Idempotency-Key` are mandatory and the action is audited.

Withdrawal cancellation is forbidden after a transaction is signed/broadcast/on-chain. Security hold/release is available only before signing.

Private keys, mnemonic, Telegram token and JWT secret are never returned by admin APIs.

## Runtime switches

The admin can set:
- `tradingPaused`
- `depositsPaused`
- `withdrawalsPaused`

The trading orchestrator and blockchain workers read these values from MongoDB. Financial product constants (5 trades, 10 minimum principal cycles, yield range, referral rate, deposit/withdrawal minimums) remain deployment configuration in this version and are exposed as read-only in `/admin/settings` to avoid accidental retroactive changes.

## Audit

Sensitive admin changes record actor, action, target, before/after snapshot, reason, hashed source IP, request id and timestamp in `admin_audit_logs`.
