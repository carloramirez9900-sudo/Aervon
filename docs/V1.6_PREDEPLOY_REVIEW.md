# AERVON v1.6 — revisión integral pre-despliegue

## Correcciones aplicadas

- Los endpoints autenticados de usuario ahora validan **JWT + sesión activa + cuenta ACTIVE** en cada request.
- La rotación de refresh tokens es atómica para evitar doble consumo concurrente.
- El frontend usa una única renovación de sesión en vuelo para evitar carreras entre múltiples respuestas 401.
- Las acciones admin de HOLD/RELEASE/CANCEL de retiros usan transiciones atómicas para no competir con el worker de firma.
- Un retiro `SIGNED` con payload inconsistente pasa a `SECURITY_HOLD`; sus fondos no se liberan automáticamente.
- Se añadió `GET /health` para readiness de Railway/MongoDB.
- Se añadieron headers básicos de seguridad del API y `X-Request-ID` a CORS.
- Se añadió `npm run start:prod` para el backend.
- Se eliminaron artefactos generados de TypeScript/Vite que no deben mantenerse en el source bundle.

## Verificaciones realizadas

- Revisión estática de rutas y dependencias entre módulos.
- Revisión de auth, ledger, depósitos, sweeps, retiros, ciclo simulado, dashboard y RBAC admin.
- Transpilación sintáctica de todos los archivos `.ts`/`.tsx` mediante TypeScript: 0 errores sintácticos.
- Búsqueda de secretos reales antes de empaquetar.

## Pendiente antes de producción

1. Ejecutar `npm install && npm run build && npm test` en un entorno con acceso normal al registry de npm.
2. Ejecutar lo mismo dentro de `frontend/`.
3. Configurar MongoDB Atlas como replica set (Atlas ya lo provee) para transacciones multi-documento.
4. Configurar Telegram Bot y webhook HTTPS.
5. Configurar BSC RPC, contrato USDT, Treasury y wallets operativas.
6. Mover `BSC_HD_MNEMONIC` y `BSC_WITHDRAWAL_PRIVATE_KEY` a un signer aislado/KMS/MPC antes de manejar capital relevante.
7. Cambiar el refresh token de `sessionStorage` a HttpOnly cookie/BFF antes de producción pública; la implementación actual funciona, pero una app financiera debería reducir exposición a XSS.
8. Definir `FRONTEND_ORIGINS` y `VITE_API_URL` con las URLs finales de Railway/custom domain.
9. Configurar Railway health check a `/health`.
10. Realizar pruebas end-to-end en BSC testnet o entorno controlado antes de activar fondos reales.

## Nota sobre trading mostrado

Las operaciones del motor siguen siendo `SIMULATED` y la API expone esa condición. No se generan `exchangeOrderId` ni se presentan como órdenes realmente ejecutadas en un exchange.
