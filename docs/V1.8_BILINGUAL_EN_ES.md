# AERVON v1.8 — English / Spanish

## Scope

The AERVON frontend now supports English (`en`) and Spanish (`es`) across registration, login, user dashboard, wallet, trading, history, compound reinvestment, referrals, help, profile, and all six admin views. English is the default when no valid preference has been stored.

- The EN / ES selector is shown on login/registration, user pages, user Profile, admin desktop sidebar and admin mobile header.
- Changing language does **not** change financial rules or API identifiers; backend enum/status values remain language-neutral.
- Before registration, `aervon.language` is kept in the browser's local storage (no tokens are stored there for this feature).
- Registration submits `preferredLanguage` so account creation persists the choice atomically in MongoDB.
- Login and refresh return `user.preferredLanguage`; login restores the account's choice.
- An authenticated language change calls `PATCH /auth/preferences/language`, which requires a valid, non-revoked session and validates the `en | es` allowlist.
- The existing `GET /auth/profile` exposes `preferredLanguage`.
- Local UI copy, help articles, statuses, and common API error messages have bilingual mappings. Dates, USDT number formatting, and country display names follow the active locale.

## New API

`PATCH /auth/preferences/language`

Headers: `Authorization: Bearer <access-token>`, `Content-Type: application/json`

Request: `{ "language": "es" }`

Response: `{ "preferredLanguage": "es" }`

Unsupported values return HTTP 400. Anonymous requests return HTTP 401.

## Implementation locations

- `src/database/schemas/user.schema.ts` — `preferredLanguage` with default `en`.
- `src/auth/auth.controller.ts`, `src/auth/auth.service.ts` — authenticated preferences endpoint, registration and token response.
- `frontend/src/i18n/` — locale state and translation dictionaries. This is a lightweight React context implementation; it deliberately introduces no extra npm dependencies.
- `frontend/src/components/LanguageSelector.tsx` — EN / ES control.
- `frontend/src/test/i18n.test.tsx`, `test/auth-language.spec.ts` — frontend and backend unit tests.

## Verify locally

1. Backend: run `npm install`, then `npm run build` and `npm test`.
2. Frontend: `cd frontend && npm install && npm run build && npm test`.
3. In an incognito browser, confirm login loads in English and ES changes the copy.
4. Complete registration in Spanish and confirm `GET /auth/profile` reports `preferredLanguage: es`.
5. Sign out, sign in again and confirm the account preference is restored.
6. Test desktop and mobile admin views and Help Center in both languages.

**Release gate:** npm package installation and integration tests were not executed in this offline environment. Do not treat this build as production-validated until both builds and tests pass and the above end-to-end flows are checked in a staging deployment.
