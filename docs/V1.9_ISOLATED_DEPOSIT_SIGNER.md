# AERVON v1.9 — isolated signer for BEP-20 deposit sweeps

## What changed

- The **public NestJS backend only needs `BSC_DEPOSIT_XPUB`** to generate a separate address for each user. All mnemonic/private-key fallbacks were removed from `WalletDerivationService`.
- Deposit sweeps ask a **separate private service** to sign one precisely bounded USDT transaction, addressed **exclusively to the configured Treasury**. The signer does not provide arbitrary signing or an HTTP endpoint to transfer funds elsewhere.
- HMAC SHA-256 signed requests (timestamp, raw JSON), 30-second validity, durable unique `requestId` persisted in an independently credentialed signer database. The public API verifies signed tx source, token, destination, value, chain ID and tx hash before broadcasting.
- MongoDB lease per deposit address, immutable batch row IDs, signing-intent persistence before calling the signer, signed raw transaction persistence before broadcasting, rebroadcast of **the same** payload after restart, and at least the configured chain confirmations + matching Transfer receipt log before marking only those rows as `SWEPT`.
- Lost response: client asks the signer to **recover the same** previously signed transaction. If the signer is stuck in PROCESSING, or a transaction reverts, automatic signing is held for manual investigation. Never reset those fields directly in production.
- The sweep amount is the exact sum of recorded *credited* deposits in the selected batch, not the wallet's entire on-chain USDT balance.

## Private deployment layout

Create **three** Railway services from this repository:

| Service | Public domain | Start | Secrets |
| --- | --- | --- | --- |
| Backend | Yes | existing `npm run start:prod` | XPUB, HMAC secret, BSC RPC, gas-wallet key (existing architecture), no mnemonic |
| Frontend | Yes | existing frontend start | `VITE_API_URL` only |
| Deposit signer | **NO**; Railway private networking only | `npm run start:signer` | mnemonic, HMAC secret, restricted signer MongoDB credentials, Treasury, token, BSC RPC, matching XPUB |

Signer Railway config file: `/railway.signer.toml`, root directory `/`. Set `PORT=3001`, connect to its private hostname such as `http://aervon-signer.railway.internal:3001` from the backend. The backend intentionally rejects non-`.railway.internal` signer URLs in production. Do not expose `/internal/sign-sweep` or `/internal/recover-sweep` publicly.

The **signer should have its own MongoDB user restricted to `aervon_signer`**. It needs MongoDB for idempotent signature persistence. The signer stores signed raw transactions (not mnemonic), request hashes and request IDs. Keep this collection and its audit history.

### Values for Backend (Railway)

```dotenv
BSC_DEPOSIT_XPUB=REPLACE_WITH_MATCHING_PARENT_XPUB
BSC_SIGNER_INTERNAL_URL=http://aervon-signer.railway.internal:3001
BSC_SIGNER_SHARED_SECRET=REPLACE_WITH_RANDOM_SECRET_AT_LEAST_32_BYTES
BSC_SIGNER_MAX_GAS_PRICE_GWEI=20
BSC_TREASURY_ADDRESS=0xYOUR_TREASURY
BSC_RPC_URL=https://YOUR_BSC_RPC
BSC_USDT_CONTRACT=0x55d398326f99059fF775485246999027B3197955
BSC_GAS_WALLET_PRIVATE_KEY=REPLACE_WITH_LIMITED_BNB_GAS_WALLET_KEY
BSC_REQUIRED_CONFIRMATIONS=12
```

**The backend must not have `BSC_HD_MNEMONIC` or `SIGNER_HD_MNEMONIC`.** `BSC_SIGNER_SHARED_SECRET` is not a wallet key.

### Values for isolated signer (Railway PRIVATE service)

See `/.env.signer.example`. Keep the master recovery phrase **only** in its secret store (preferably a managed KMS/HSM/MPC signer for meaningful production balances). The mnemonic **must correspond to the very same XPUB that issued any existing addresses**: never generate a new seed if the platform has already issued/funded deposit addresses.

### Creating a seed and XPUB

On a trusted, offline local machine (not Railway builds): `npm run generate:deposit-hd`. This prints a mnemonic, a matching parent XPUB for `m/44'/60'/0'/0`, and a test-derived address (`index=1`). Back up the mnemonic **offline**. Keep it outside source control, chat and logs. If an existing wallet has already issued addresses, **do not create a new seed**: use the existing phrase and independently verify that its parent XPUB matches the configured XPUB and stored address at index 1.

### Safety limitations and launch gates

This is **software isolation, not HSM**: environment variables in the isolated process are still recoverable if that service is compromised. The existing separate **gas wallet and withdrawal hot-wallet keys remain in the main backend** in this version and also need moving to a dedicated signer/KMS before handling substantial customer funds. Do not imply that all wallet keys are now isolated.

- **Do not enable real funds without:** dependency installation, full `npm run build` and tests, end-to-end BSC testnet/fork sweeps and failure/restart scenarios, permission and secret-store checks, independent security review, and appropriate financial/legal disclosures.
- The code requires *a fully private signer with correct secret matching*; when missing it fails closed (no sweep).
- If a signature was created and persisted but transaction broadcast/confirmation stalls, the system rebroadcasts the **exact same signed payload**. A permanently stuck, replaced, reverted or ambiguous transaction requires operator investigation, not automatic re-signing.
- Protect `BSC_GAS_WALLET_PRIVATE_KEY` and limit available BNB. A hot gas key in the main backend is still an outstanding risk.
- Keep deposit monitoring and user-ledger credits separate from sweep execution. A successful sweep does not create a second user credit.
- If older data has ambiguous `SWEEP_FAILED` records from v1.8 or prior, reconcile them against BSC transaction history before enabling this worker.

### Test checklist

1. `node --test signer/validation.test.mjs` (dependency-free policy and HMAC checks).
2. `npm install`, `npm run build`, `npm test` (full checks, not completed here because dependency installation is unavailable).
3. Offline compare the signer parent XPUB, backend XPUB, and an already allocated derivation index.
4. With isolated signer on testnet/fork, confirm invalid HMAC, stale timestamp, wrong address, forbidden amount, high gas price and mismatched XPUB are rejected.
5. Check sweep batch amount, gas funding, durable signature recovery after simulated client timeout, nonce conflicts, duplicate workers, reorg and receipt-log verification.
6. Ensure private signer has no public Railway domain, no unrestricted ingress, and separate credentials.
